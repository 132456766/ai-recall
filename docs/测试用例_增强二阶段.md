# 测试用例文档 · 增强二阶段（知识点库 / 书籍 / 双版本解析 / 自动识别与自动保存）

> 关联：PRD（模块 A/B/C/F/I/K）、UI/UX 设计文档（新粗野主义组件规范）、开发规划文档（第四章 API 契约）。
> 本阶段在前序「MVP / V1.0 / V2.0 / 增强一」基础上，新增 4 项能力，全部沿用本地优先（IndexedDB + Mock AI）架构，UI 通过门面层 `services/api.js` 调用，真实后端仅需替换 `api.real.js` / `bend.js` 两层。
> 运行模式：`npm run dev`（默认 `mock`，无需后端即可演示）。切换真实后端：`.env` 设 `VITE_API_MODE=real`、`VITE_API_BASE=<后端地址>`。

## 1. 功能验收用例（GIVEN-WHEN-THEN）

### 1.1 可自主添加任意学科知识点（KP 库）

| 编号 | 场景 | GIVEN | WHEN | THEN |
| --- | --- | --- | --- | --- |
| KP-01 | 添加自定义知识点 | 录入页学科=数学 | 在「知识点标签」输入「导数定义」并回车 | 该标签加入本题知识点；持久化进知识点库（meta）；下次该学科下拉/建议可见 |
| KP-02 | 知识点库复选 | 数学已有知识点库[集合,函数] | 点击库中的「集合」建议徽章 | 标签被选用（高亮）；再次点击取消选用 |
| KP-03 | 重名拦截 | 数学已存在「集合」 | 再添加「集合」 | 不重复入库（db.addCustomKP 返回 null，门面 code≠200） |
| KP-04 | 空名拦截 | —— | 输入纯空格并回车 | 不入库，无报错 |
| KP-05 | 知识树可见 | 知识点已入库但未用于任何错题 | 打开侧边栏「知识树」 | 该学科节点展开可见该知识点（库与错题合并展示） |
| KP-06 | 按学科隔离 | 数学有「集合」、物理有「牛顿第二定律」 | 切换学科查看建议 | 各自仅显示本学科知识点 |

### 1.3 AI 给出答案 + 双版本解析

| 编号 | 场景 | GIVEN | WHEN | THEN |
| --- | --- | --- | --- | --- |
| AN-01 | 生成答案 | 已填写题目 | 点「AI 生成答案与解析」 | `answer` 填入答案区；`analysis`(精简版)填入解析文本框；`analysisDetail`(详细版)仅出现在右侧预览 |
| AN-02 | 精简版写入错题本 | 生成后 | 保存本题 | 错题卡片「解析」展示的是**精简版**；详细版存于 `analysisDetail` 字段 |
| AN-03 | 详细版仅预览 | 生成后 | 在 AI 预览点「查看详细解析」 | 展开完整结构化解析（考查要点/思路/步骤/易错/举一反三）；不覆盖精简版 |
| AN-04 | 错题卡片看详细 | 已保存含详细版 | 卡片点「解析」展开 → 「详细解析（AI 版）」 | 显示详细版内容 |
| AN-05 | 仍可手动编辑 | 生成后 | 修改解析文本框 | 以用户编辑为准（精简版可覆盖） |
| AN-06 | 公式识别 | 题目含 `$f(x)=x^2+2x+1$` | 生成 | 详细版标注涉及公式；极值题给出「最小值 0」结论 |

## 3. API 契约（新增端点，对齐开发规划文档第四章）

| 方法 | 端点 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/kps` | 知识点库（按学科分组） |
| POST | `/api/v1/kps` | 新增知识点 `{subject, label}` |
| GET | `/api/v1/books?subject=` | 书籍列表（按学科过滤，含通用） |
| POST | `/api/v1/books` | 新增书籍 `{title, author?, subject?, note?}` |
| PUT | `/api/v1/books/:id` | 更新书籍 |
| DELETE | `/api/v1/books/:id` | 删除书籍 |
| POST | `/api/v1/ai/solve` | 生成答案+双版本解析（返回 `answer/analysis/analysisDetail`） |

> 门面层 `api.js` 已同步导出 `getKPs/addKP/addBook/listBooks/updateBook/deleteBook`；`api.mock.js` 与 `api.real.js` 实现一致（mock 走本地 IndexedDB，real 走上述端点）。

## 4. 数据模型变更

- `errors` blob 新增字段：`analysisDetail`（详细解析）、`bookId`（关联书籍 id）；`source` 结构保持不变 `{type, name}`，书籍通过独立 `bookId` 关联。
- 新增对象库 `books`（keyPath `id`，索引 `by_subject`）。
- 知识点库存于 `meta('custom-kps')`：`{ [subjectId]: [{id,label}] }`。
- 草稿存于 `localStorage('recall-entry-draft-v2')`（仅文本字段，不含图片）。

## 5. 已知限制（增强二）

- AI 答案/解析为 **Mock 模板生成**（结构完整、含公式特例，但非真实推理）；接入真实大模型只需实现 `/api/v1/ai/solve`，前端零改动。
- 书籍/知识点库为**本地持久化**；多端同步依赖后端账号体系（见 L 模块规划），当前未跨设备。
- 自动保存为**单草稿**（仅保留最近一份新建草稿），不含图片（base64 体积超限）；真实提交以「保存」按钮落库为准。
- B 端、云同步、支付仍为本地面板，真实接入仅替换 `api.js` / `bend.js` 两层。
