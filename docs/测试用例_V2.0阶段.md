## 4. 真实后端契约对接（VITE_API_MODE=real）

本阶段新增「可切换的真实后端契约骨架」，将 Mock 层与真实后端对齐，UI / Store / 存储逻辑零改动。

| 文件 | 职责 |
| --- | --- |
| `src/config.js` | 读取 `VITE_API_MODE` / `VITE_API_BASE`，导出 `API_MODE`/`IS_REAL` |
| `src/services/http.js` | 真实传输层：base URL、鉴权头、信封解包 `{code,message,data}`、错误码映射、SSE 流式 `streamChat` |
| `src/services/contract.js` | 端点契约（与规划文档「第四章 API 契约」对齐）+ 错误码表 + 信封示例 |
| `src/services/api.mock.js` | 原 `api.js` 的 Mock 实现（IndexedDB + Mock AI），默认分支 |
| `src/services/api.real.js` | 真实后端实现，方法签名/返回信封与 mock 完全一致 |
| `src/services/api.js` | **门面分发器**：按 `API_MODE` 在 mock/real 间切换，对外同名导出 |
| `src/lib/bend.mock.js` | B 端 Mock（localStorage） |
| `src/lib/bendApi.js` | B 端真实客户端（调用 contract 机构端点） |
| `src/lib/bend.js` | B 端门面分发器，统一返回 Promise（mock 以 `Promise.resolve` 包裹） |
| `.env` / `.env.example` | 运行模式与后端基地址配置 |

**切换方式**（无需改任何 UI 代码）：
1. 复制 `.env.example` → `.env`；
2. 设 `VITE_API_MODE=real`、`VITE_API_BASE=<后端地址>`；
3. 重启 `npm run dev`。

**契约验收用例（对接骨架）**
| 用例 | 操作 | 预期 |
| --- | --- | --- |
| C-TC1 | 设 `VITE_API_MODE=mock` 启动 | 走 mock 分支，无需后端即可完整运行（默认） |
| C-TC2 | 设 `VITE_API_MODE=real` 启动 | 门面切到 `api.real.js` / `bendApi.js`，请求发往 `VITE_API_BASE` |
| C-TC3 | 后端返回非 200 code | `http.js` 抛 `ApiError`，`api.real.js` 收敛为 `{code,message,data:null}`，UI 表现与 mock 失败一致 |
| C-TC4 | `chatStream` 真实 SSE 流 | 逐行解析 `data:{delta}` 并回调 `onToken`，遇 `[DONE]` 结束 |
| C-TC5 | `Admin` 在 real 模式 | 全部 `await` 调用 B 端门面，席位数/账号/分析随机构后端返回 |

## 5. 已知限制（V2.0）

- B 端能力在 **mock 模式**下为本地模拟（localStorage）；切换 `real` 后由真实机构后端提供（端点见 `contract.js`）。UI（`Admin.jsx`）通过门面层调用，无需改动。
- 付费转化（支付下单、发票、权益开通）在真实的 `subscribe` 端点之上仍为状态机演示，需接支付网关。
- 商业化权益（去广告/云同步/合规审计）与 C 端账号体系的真实打通，依赖后端账号与权限服务（见 L 模块规划）。
- 真实后端未实现时，保持 `VITE_API_MODE=mock` 即可完整演示全部功能。
