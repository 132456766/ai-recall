# 测试用例文档 · 增强四阶段（全部学科可 AI 搜索 + 快速添加学科/书籍）

> 阶段目标：在「增强三 AI 智能搜索」基础上，将 AI 搜索的学科覆盖扩展到**全部学科**——内置 9 学科、18 个大学学科预设，以及用户自主添加的任何自定义学科；同时支持在**搜索页直接快捷添加学科与书籍**，添加后即可被 AI 搜索命中。
> 模式：本地优先（mock），`VITE_API_MODE=real` 时由后端 `/api/v1/ai/search` 承接，前端零改动。
> 验证环境：`npm run build` 通过；`npx vitest run` → 74 passed（`src/lib/search.test.js` 由 12 项增至 19 项，新增 7 项）。

## 3. API 契约（对齐 `src/services/contract.js`）

| 方法 | 端点 | 请求 | 响应 data |
| --- | --- | --- | --- |
| `search(query)` | `POST /api/v1/ai/search` | `{ query: string }` | `{ query, intent, results, memos, books, summary, total }` |

- 学科解析改为**动态别名表**：由 `aiParseSearch(query, {subjects})` 的 `subjects` 实参（内置 + 自定义 + 大学，来自 `db.getCustomSubjects()`）构建，无需新增字段。
- `intent.subject` 现已能解析为任意学科的**真实 id**（含 `subj_xxx` 自定义 id），检索与摘要均按真实 id 关联。
- `addSubject(label)` / `addBook(book)` 沿用增强一/二的契约与门面，搜索页直接复用，无需新增端点。

## 5. 已知限制（增强四）

- AI 意图解析仍为**本地规则解析**（Mock），非大语言模型；学科命中依赖「查询包含学科名/缩写」子串匹配。若用户自定义学科名与内置学科名存在包含关系（如自定义「数学分析」与内置「数学」），按「更具体的词优先」规则处理，已规避「高等数学」被「数学」误命中。
- 大学学科缩写词典覆盖 18 个预设学科的常见缩写（高数/大物/线代/计网/马原/微经/宏经…）；未在词典中的生僻缩写不会触发回退，但用户可直接输入完整学科名命中（因为学科标签本身已被动态纳入别名表）。
- 真实后端模式下，`search` 仅透传 `query`；学科解析由后端按自身学科表实现，前端展示依赖 `intent.subject` 与本地 `subjectMap` 对齐（建议后端返回学科 id 与前端一致）。
